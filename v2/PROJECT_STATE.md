# GlitterFX V2 — Current Work

## Branch
`v2-engine`

## Current objective
**Publish the 2.0.0-alpha.0 prerelease** (owner action: needs npm access to the `@glitterfx` scope; steps in `RELEASE.md`), then collect real-device feedback.

After the alpha: run a real-hardware performance pass, then follow `POST_ALPHA_EFFECTS.md`. First shipping targets are Glitter Shimmer, cheap catalog additions, pointer interaction, Shape Targets, shaped particles, custom palettes, and a Web Component. WebGPU remains deferred until a stateful effect actually needs it.

- Step 1.2: `new GlitterFX(element, options)` with `start/stop/resize/update/destroy`, normalized/clamped config shared by all backends, `BackendDescriptor`/`BackendInstance` contract, global `registerBackend()` or per-instance `backends`. Explicit renderer is respected (clear error if unregistered/unsupported, container left untouched); `auto` picks webgl then canvas. Core owns mounting (surface behind content via `isolation`), ResizeObserver sizing with quality DPR cap (eco 1, balanced 1.5, high 2), and the RAF loop (clamped delta, `speed` scales effect time, stop freezes time). Changing `renderer`/`effect` via `update()` rebuilds the backend only when the resolved backend changes. Canvas and WebGL backends mount, size and dispose real surfaces (no effect drawing yet). Verified with a fake backend in tests and both real backends in headless Chromium.
- Step 1.3: `v2.html` playground with live `GlitterFX` instance(s): backend (auto/canvas/webgl/compare), quality, density, speed, size, brightness, glow, seed, pause, copy config. Every control goes through `fx.update()` on the running instance (browser-verified: same instance after slider, quality, seed and backend changes). WebGL backend loads lazily. Core now creates the backend before touching the DOM or the current instance, reads the global registry lazily, and exposes `unregisterBackend()`.
- Step 2.1: `@glitterfx/effects` Star Field semantics: mulberry32 PRNG, `createStarField(renderer, config)` into typed arrays (position, depth, size, intensity, palette color, twinkle phase/rate/amplitude, flare), per-backend/per-quality budgets (canvas 350/800/1500, webgl 2500/6000/14000 at density 1 after 2.4 tuning), palettes (starlight, aurora, ember, frost), shared drift/parallax/radius/alpha/profile formulas. WebGL gets the Canvas field unchanged plus faint dust stars. Backends now depend on `effects` (boundary test updated).
- Step 2.2: Canvas Star Field. Typed-array field from `effects`, parallax drift with wrap margin, depth-aware size/alpha, twinkle, additive compositing, sprites baked per palette color from the shared `starProfile` (flare sprites with diffraction spikes), rebuilt lazily when glow/palette change. Field regenerates only on seed/density/quality/palette changes. Tests: identical draw calls for the same seed/time, positions stable under appearance changes, density scaling. Measured about 1.5 ms/frame (balanced) and 3 ms/frame (high) at 1280x720 on a single-core software-rendered headless Chromium. Playground gained a palette control.
- Step 2.3: WebGL Star Field. `THREE.Points` with static attributes (position+depth, size/intensity/flare, color, twinkle) uploaded once per field; custom GLSL mirrors the shared drift/parallax/wrap, radius, alpha, twinkle and core/halo/spike profile; premultiplied additive blending; sub-pixel energy conservation; hardware point-size ceiling respected. Per frame only `uTime` changes (test asserts attribute versions stay constant across 120 frames and appearance updates). Geometry rebuilds only on seed/density/quality/palette changes. Renders the Canvas field star-for-star plus faint dust (6000 vs 800 stars at balanced).
- Step 2.4: Compare mode shows Canvas and WebGL side by side with the same seed/config and synchronized effect time (both instances start in the same frame). Tuned against screenshots at default and extreme settings (glow 1, size 2, brightness 1.4): WebGL dust reduced (size 0.5, intensity 0.3, budgets 2500/6000/14000) so primary stars dominate on both backends; flare halo 2.5x and steeper spike falloff. Backend changes with one config value (`renderer`).
- Step 3: engine primitives in `@glitterfx/effects/src/engine`: fixed-layout `ParticleStore` (p, v+hash, shape, time channels), budgets/`particleCounts`, prefix-stable `generateParticles`, emitters (box, sphere, ring, triangular), closed-form behaviors (wrap, twinkle, drag, forced motion, life fade, loop age, turbulence, curl velocity, stateless curl advection), shared `particleProfile`. `ParticleEffect` = generate + prepare + sample. Canvas and WebGL now each have ONE generic particle renderer; WebGL reads the store directly as attributes and adds only the effect's GLSL `sampleParticle` (mirrors in `backend-webgl/src/glsl`, `src/effects`). Star Field moved onto it with proof of no change: identical generated values, identical Canvas draw-call fingerprint, and a 0-difference pixel diff for both backends against pre-refactor renders. `galaxy` built on the same primitives (no engine changes). New `apps/playground/fixtures.html` renders any effect/backend at a fixed time for visual review and pixel diffs.
- Step 4.1: `fx.transitionTo(effectOrChanges, { duration, type })` resolving true on completion, false when cancelled or superseded; `cancelTransition()` reverts; a new transition or `update()` completes the running one first; progress follows the real clock (not the 100 ms simulation clamp, so slow devices finish on time) and freezes while stopped or hidden. Crossfade lives in core (two instances, CSS opacity, outgoing destroyed at the end) and is the fallback for any backend. Optional `BackendInstance.beginTransition/setTransition/endTransition` for in-instance transitions: Canvas and WebGL both implement dissolve (per-particle hash threshold) and morph (particle i of A travels to particle i of B, staggered by hash; WebGL evaluates both effects' GLSL in one combined shader, no per-frame JS). Playground has a transition selector; all 6 backend/type combinations verified in Chromium, one surface left afterwards.
- Step 4.2: shared `haze` option (0..1, default 0 = no cost). Effects may return up to 6 haze blobs per frame: Canvas draws cached gradient sprites, WebGL a full-screen pass with procedural noise wisps (richer). Depth-of-field `soft` sample channel (wider core, same energy): Canvas uses 3 cached sprite levels, WebGL is continuous. Galaxy got a warm core glow and disk light; Star Field nebula clouds. Haze fades correctly through dissolve/morph. `createWebGLBackend({ postprocess })` hook for optional post effects (e.g. bloom), off by default; `webglBackend` is the plain instance.
- Step 5.1: galaxy (built on the Step 3 primitives, polished in 4.2): tilted two-arm log spiral, rigid pattern rotation with radial breathing, bulge + inter-arm field stars, far-side softness, core/disk haze. WebGL adds 22k faint disk stars at balanced vs 1.8k on Canvas.
- Steps 5.2-5.4: `supernova` (periodic bursts: shock shell, cooling ejecta, pulsing remnant; drag closed form, flash + remnant haze), `ember-storm` (buoyancy vs drag, wind, turbulence sway, flicker, cooling over life, near-ember bokeh via `soft`, warm ground haze), `curl-flow` (stateless re-integration through a divergence-free field, wrapped at the edges, color bands by spawn position). New generic WebGL capability: effects may declare motion trails; trail samples are the same particle evaluated slightly in the past (no history buffers), used by ember-storm (4) and curl-flow (12). No engine changes were needed for any of the three effects; only the trail option was added to the generic renderer. Five reference effects now cover stars, orbital motion, bursts/lifetimes, buoyancy/drag and curl flow.
- Step 6: `renderer` accepts an ordered fallback list (`['webgl', 'canvas']`); `capabilities()` reports supported renderers, what `auto` picks, and reduced-motion preference. The loop pauses while the tab is hidden or the container is offscreen (`pauseWhenHidden`, default true) and resumes after; `animating` exposes it. `reducedMotion: 'auto' | 'static' | 'ignore'` (default auto): with reduced motion a still frame is drawn on start/resize/update and transitions are instant; runtime preference changes are honored. WebGL context loss: rendering pauses, and on restore the layers are rebuilt deterministically (verified in Chromium with WEBGL_lose_context, including a transition afterwards). `@glitterfx/react`: `<GlitterFXBackground>` (create on mount, destroy on unmount, shallow-diffed `update()`, optional `transition` for effect changes, SSR-safe, StrictMode-safe); react is a peer dependency; boundary test extended.
- Step 7: the full V1 catalog (26 numbered effects + `bending-chaos`) runs on V2. Five were already V2 effects (`galaxy-spiral` and `ember-drift` resolve to `galaxy` and `ember-storm` via `V1_ALIASES`). The other 22 are parameter sets (`effects/src/catalog.ts`) over six closed-form archetypes in `effects/src/archetypes`: drift (petals, snow, leaves, confetti, bubbles, meteors, sand, fireflies, underwater), radial (stream/sync/orbit: ray burst, bending chaos, petal burst, heartbeat, spiral drift, emerald shimmer, cosmic dust), wave (wave particles, aurora veil), fountain (lava eruption, dancing waves), quantum (quantum field), curl (curl flow now uses it; plasma storm). WebGL GLSL is generated per archetype from the same parameters (`backend-webgl/src/archetypes.ts`); hand-written GLSL remains for star-field, galaxy, supernova, ember-storm. V1 palettes ported (magma reordered hot -> cool for cooling; new `borealis` for the aurora curtains). Canvas gained optional short trails (`trail.canvas`), same falloff as WebGL: meteors, sand, lava, ray burst, plasma and curl flow now streak on Canvas too. Fixed a latent Step 5 bug: morphs into/out of effects reading `uPaletteSize` (supernova, ember-storm, all archetypes) failed to compile; now renamed per side and tested for every effect, plus a Chromium morph check across archetype pairs. All 27 effects reviewed on both backends.
- Step 8 (WebGPU): assessed and deferred, not built. The roadmap requires a real improvement (very high counts, compute simulation, advanced post). Every V2 effect is closed-form, so WebGL already runs all motion in vertex shaders with no per-frame CPU work; counts are fill-rate bound, which WebGPU does not change. Compute only pays off for stateful simulation (boids, collisions, fluid), and no effect needs it. Post effects are covered by the WebGL `postprocess` hook. Revisit trigger: a requested stateful effect or a measured WebGL ceiling on real hardware.

Proven outside the workspace: tarballs installed into a clean project, Node ESM import, Vite production build, and the built site rendering one hero on Canvas and one on WebGL in Chromium; `examples/browser.html` verified on both renderers with morph transitions. Docs: README rewritten as the package front page, `MIGRATION.md` (V1 -> V2 API, config keys, effect aliases, palettes), `RELEASE.md`. V1 untouched (`glitterfx` on npm is a different package; governance check passes).
- Galaxy HD rework: rebuilt from five stellar populations (smooth warm bulge, faint old disk, young blue arm stars with a one-sided spread that leaves dust lanes on the inner arm edges, 26 pink star-forming knots of varied size, soft out-of-focus arm glow), per-population brightness so dense regions keep detail instead of clipping, physical (not angular) arm width, arms emerging gradually from the bulge. WebGL budget raised to 12k/36k/70k; its extra particles never join knots and are dimmed in small views (`GALAXY_FULL_EXPOSURE`), so brightness holds from small cards to full-screen heroes. Canvas unchanged in brightness.
- Effect settings and opacity: effects may declare `params` (range, default, step, label); `config.params` carries values (validated finite numbers in core, clamped/snapped per effect by `resolveParams`), passed to `generate`, and a change regenerates particles (`needsRegenerate`). Galaxy declares `arms` (1-8, default 2) and `twist` (0.8-4, default 2.3); arm width narrows and single arms dim so any count keeps detail; no shader change needed since arms are generation-time. New shared `opacity` (0-1, default 1) applied by core to the surface element for every effect and renderer at no render cost, interpolated through crossfades and in-instance transitions. Playground: opacity slider and a per-effect settings section built from declarations (applied on release through the selected transition). React diff compares `params` by value.
